# Сайт-шаблон с админ-панелью

Готовый сайт-визитка из трёх страниц — Главная, Работы, Контакты — и админ-панель, в которой владелец сам меняет тексты, фото, страницы, меню, цвета и шрифты — без программиста.
Ставится на сервер **одной командой** и сразу открывается на поддомене, например `https://ivan.artwillkrd.ru`.

## Быстрый старт

На сервере (Ubuntu 22.04/24.04 или Debian 12, вход под root):

```bash
curl -fsSL https://raw.githubusercontent.com/TS466-hub/artwill-site-template/main/install.sh | sudo bash -s -- ivan
```

Через 2–3 минуты команда напишет адрес сайта, адрес админки и пароль:

```
Готово!
   Сайт:          https://ivan.artwillkrd.ru/
   Админ-панель:  https://ivan.artwillkrd.ru/admin/
   Пароль:        ••••••••••••••
```

- `ivan` — имя сайта, к нему приписывается `artwillkrd.ru`. Можно указать полный домен: `… -- studio.example.ru`.
- Следующие сайты на этом же сервере: `sitectl add maria`.
- Чтобы сайт открылся, адрес должен вести на сервер (DNS) — см. ниже.

## DNS: как поддомены попадают на сервер

**Вариант 1. Один общий сервер для всех учеников (рекомендуется).**
Один раз добавьте в REG.RU (Домены → artwillkrd.ru → Управление зоной) запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `*` | IP общего сервера |

После этого любой новый поддомен сразу ведёт на этот сервер, и новый сайт — это одна команда `sitectl add имя`, без захода в DNS.
Основной сайт `artwillkrd.ru` и `www` это не затрагивает: у них свои записи. Почту (MX) не трогайте.

**Вариант 2. У ученика свой сервер.**
Для каждого такого сайта нужна своя A-запись `имя → IP его сервера` (она важнее общей `*`).
Добавить вручную в REG.RU или со своего компьютера через API:

```bash
./tools/regru-dns.sh add ivan 1.2.3.4
```

Перед первым использованием API в REG.RU: Настройки → «Настройки API» — задайте пароль для API и добавьте IP своего компьютера в разрешённые.
Там же: `wildcard IP` (запись `*`), `remove имя IP`, `list`.

Если на момент установки DNS ещё не работает (запись только что добавили — интернету нужно до часа, чтобы её увидеть), сайт создаётся без HTTPS, и админка уже работает по http.
Сервер сам пробует получить сертификат каждые 20 минут. Проверить вручную:

```bash
sitectl ssl ivan.artwillkrd.ru
```

## Управление сайтами на сервере

| Команда | Что делает |
|---|---|
| `sitectl add ivan` | создать сайт `ivan.artwillkrd.ru` |
| `sitectl list` | список сайтов, их состояние и HTTPS |
| `sitectl password ivan` | выдать новый пароль от админки (если владелец забыл) |
| `sitectl ssl ivan` | получить HTTPS-сертификат |
| `sitectl update` | обновить код шаблона из GitHub и пересобрать все сайты (их содержимое не меняется) |
| `sitectl backup` | архив содержимого и заявок всех сайтов в `/srv/sites-backup` |
| `sitectl remove ivan` | отключить сайт (данные переносятся в `/srv/sites-removed`) |
| `sitectl smtp` | почтовый ящик, с которого все сайты отправляют письма о заявках |
| `sitectl config` | базовый домен для коротких имён (по умолчанию `artwillkrd.ru`) и почта для Let's Encrypt |

Один сайт занимает около 50–80 МБ памяти: на сервере с 1 ГБ спокойно живут 8–10 сайтов, с 2 ГБ — 20 и больше.
Let's Encrypt выдаёт не больше 50 новых сертификатов в неделю на один домен (`artwillkrd.ru`) — на поток учеников хватает.

## Что умеет админ-панель (`/admin/`)

| Раздел | Что в нём |
|---|---|
| **Страницы** | все страницы; визуальный редактор: текст, фото, кнопки, блоки, отмена, история версий; создать / скопировать / удалить страницу |
| **Общие блоки** | шапка с меню, подвал, форма заявки — меняются сразу на всех страницах |
| **Шаблоны блоков** | 31 заготовка: первый экран, тексты, карточки, цены, этапы, отзывы, вопросы, галерея, формы, кнопки |
| **Изображения** | загрузка фото (сайт сам уменьшает их до нужных размеров) |
| **Оформление** | цвета, шрифты (можно загрузить свой), скругление углов, размер текста, свой CSS |
| **Заявки** | все заявки с форм, выгрузка в Excel |
| **Настройки** | название сайта, почта и MAX для уведомлений о заявках, смена пароля |

Подробная инструкция для владельца сайта — [ADMIN.md](ADMIN.md).

## Уведомления о заявках

Каждая заявка сразу сохраняется в разделе «Заявки». Дополнительно владелец сам включает в админке → «Настройки»:

- **MAX** — вставить токен своего бота (business.max.ru), нажать «Найти мой ID», сохранить;
- **почта** — указать свой адрес. Для отправки писем на сервере один раз настраивается общий ящик-отправитель: `sitectl smtp` (например, `noreply@artwillkrd.ru` в REG.RU).

Кнопка «Отправить тестовую заявку» проверяет оба канала.

## Как это устроено

| Где на сервере | Что |
|---|---|
| `/opt/site-template` | код шаблона (этот репозиторий), общий для всех сайтов |
| `/srv/sites/<домен>/content` | содержимое сайта: страницы, блоки, оформление, фото — его меняет админка |
| `/srv/sites/<домен>/data` | заявки, настройки, история версий |
| `/srv/sites/<домен>/site.env` | порт, адрес, стартовый пароль |
| `/var/www/sites/<домен>/dist` | готовые страницы, их отдаёт nginx; пересобираются при каждом сохранении |
| `site@<домен>` | служба systemd (Node.js): заявки и админ-панель. Логи: `journalctl -u site@<домен> -f` |

Без баз данных и сборщиков: сайт — статические HTML-страницы, которые собирает `build.mjs` из папки содержимого. Зависимости сервера — только `busboy` и `nodemailer`.

## Разработка шаблона

```bash
cd server && npm ci && cd ..
node dev.mjs
```

Сайт — http://localhost:4173, админка — http://localhost:4173/admin/ (пароль `admin12345`). Заявки локально никуда не отправляются.

- `starter/` — содержимое, с которого начинается каждый новый сайт (страницы, общие блоки, шаблоны блоков).
- `assets/` — стили, скрипт и картинки-заглушки; `admin/` — интерфейс админки; `server/` — заявки и API админки.
- Локальная копия содержимого лежит в `.local/` — удалите папку, чтобы начать с чистого `starter/`.

Изменения в `assets/`, `admin/`, `server/`, `build.mjs` доезжают до всех сайтов командой `sitectl update`.
Изменения в `starter/` касаются только сайтов, созданных после этого.
